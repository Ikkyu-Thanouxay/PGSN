# CEK Machine Plan

## Background

PGSN syntax is similar to lambda calculus.
The current evaluator appears to use substitution-based beta reduction.
Profiling showed that substitution and shifting are called many times.

## Professor's suggestion

Study CEK / CESK machines and try compiling or evaluating PGSN using an abstract machine.

References:
- Matt Might: CEK Machines
- Matt Might: CESK Machines
- Matt Might: OO-CESK
- Harvard CS152 lecture on abstract machines
- Wikipedia: CEK Machine

## Goal

Build a small prototype evaluator before changing the real PGSN source code.

## First prototype target

Implement a tiny CEK evaluator for:

- variable
- lambda abstraction
- application
- string/integer constants
- simple built-in functions

## Reason

CEK uses environments instead of substitution.
This may reduce repeated shift/substitution operations.
